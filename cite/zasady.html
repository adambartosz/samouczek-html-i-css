Dlaczego warto znać zasady tworzenia stron?

Strona internetowa powinna być nie tylko ładna, ale również czytelna, szybka i wygodna w użyciu. Dobre nawyki od początku nauki pozwalają uniknąć wielu problemów w większych projektach.

Przestrzeganie podstawowych zasad sprawia, że kod jest łatwiejszy do rozwijania, poprawiania i współpracy z innymi programistami.

Twórz poprawną strukturę dokumentu

Każda strona powinna rozpoczynać się od podstawowego szablonu HTML.

<!DOCTYPE html>

<html lang="pl">

<head>

    <meta charset="utf-8">

    <title>Moja strona</title>

</head>

<body>

    Treść strony

</body>

</html>

Dzięki temu przeglądarka poprawnie interpretuje dokument i wie, z jakim standardem pracuje.

Używaj odpowiednich znaczników

Każdy znacznik ma swoje przeznaczenie. Nie należy używać przypadkowych elementów tylko dlatego, że wizualnie dają podobny efekt.

Zadanie Poprawny znacznik
Nagłówek strony <h1> - <h6>
Akapit tekstu <p>
Lista punktowana <ul>
Lista numerowana <ol>
Odnośnik <a>
Obraz <img>

Dzięki temu kod jest bardziej semantyczny i łatwiejszy do zrozumienia.

Dbaj o semantykę

Semantyka oznacza używanie elementów zgodnie z ich znaczeniem.

Zamiast tworzyć wszystko przy pomocy znaczników <div>, warto korzystać z elementów opisujących rolę danego fragmentu strony.

<header>

    <h1>Sklep komputerowy</h1>

</header>



<nav>

    Menu

</nav>



<main>

    Treść strony

</main>



<footer>

    Stopka

</footer>

Takie rozwiązanie pomaga przeglądarkom, wyszukiwarkom i czytnikom ekranu.

Stosuj odpowiednie wcięcia

Czytelny kod jest łatwiejszy do analizowania i poprawiania.

Dobrze sformatowany kod:

<section>

    <h2>Aktualności</h2>

    <p>Treść artykułu</p>

</section>

Źle sformatowany kod:

<section><h2>Aktualności</h2><p>Treść artykułu</p></section>

Przy większych projektach odpowiednie wcięcia są bardzo ważne.

Oddzielaj HTML, CSS i JavaScript

Każda technologia ma inne zadanie.

Technologia Przeznaczenie
HTML Struktura strony
CSS Wygląd strony
JavaScript Interakcja i logika

Zamiast pisać wszystko w jednym miejscu, lepiej używać osobnych plików.

<link rel="stylesheet" href="../css/style.css">

<script src="../js/script.js"></script>

Pamiętaj o dostępności

Nie wszyscy użytkownicy korzystają ze strony w taki sam sposób. Niektóre osoby używają czytników ekranu lub specjalnych urządzeń.

Dlatego warto:

  • dodawać opisy alt do obrazów
  • stosować nagłówki w odpowiedniej kolejności
  • używać czytelnych tekstów linków
  • zachowywać odpowiedni kontrast kolorów
  • nie ukrywać ważnych informacji wyłącznie w obrazach

Przykład:

<img src="../img/logo.png" alt="Logo szkoły">

Dbaj o szybkość działania strony

Użytkownicy nie lubią długo czekać na załadowanie strony.

Warto:

  • zmniejszać rozmiar obrazów
  • usuwać niepotrzebny kod
  • łączyć pliki CSS i JavaScript w większych projektach
  • używać nowoczesnych formatów obrazów
  • ładować tylko potrzebne zasoby

Zbyt duże pliki mogą znacząco spowolnić działanie witryny.

Testuj stronę regularnie

Nie warto pisać kilkuset linii kodu bez sprawdzania efektów.

Dobrą praktyką jest częste odświeżanie strony i kontrolowanie zmian.

Warto testować witrynę:

  • w różnych przeglądarkach
  • na komputerze
  • na telefonie
  • na tablecie
  • w różnych rozdzielczościach

Nazywaj pliki i foldery w uporządkowany sposób

Dobrze zorganizowany projekt jest łatwiejszy do rozwijania.

Przykładowa struktura:

projekt

├── index.html

├── css

│   └── style.css

├── js

│   └── script.js

└── img

    ├── logo.png

    └── tlo.jpg

Nazwy plików powinny być krótkie i jednoznaczne.

Unikaj najczęstszych błędów

  • brak DOCTYPE
  • brak zamknięcia znacznika
  • powtarzanie identycznych identyfikatorów id
  • używanie zbyt wielu divów bez potrzeby
  • brak atrybutu alt w obrazach
  • pisanie całego CSS w atrybucie style
  • nieczytelne nazwy klas
  • brak testowania strony
  • kopiowanie kodu bez zrozumienia jego działania
  • chaotyczna struktura katalogów

Złota zasada początkującego programisty

Pisz kod tak, abyś za miesiąc nadal rozumiał, co zrobiłeś.

Czytelność jest ważniejsza od sprytnych, ale niezrozumiałych rozwiązań.

Dobrze napisany kod:

  • łatwo przeczytać
  • łatwo poprawić
  • łatwo rozbudować
  • łatwo przekazać innej osobie

Większość profesjonalnych projektów powstaje właśnie według tej zasady.
