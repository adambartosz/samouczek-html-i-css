Co to jest XML

XML (Extensible Markup Language) to język znaczników do opisywania danych. Nie służy do wyglądu strony, tylko do przechowywania i przenoszenia informacji.

Jest czytelny zarówno dla człowieka, jak i dla komputera. Struktura opiera się na znacznikach podobnych do HTML, ale są one własne i dowolnie definiowane.

XML musi być dobrze sformatowany, inaczej parser go odrzuci.

Każdy element musi mieć znacznik otwierający i zamykający.

Można w nim tworzyć własne struktury danych.

Nie ma gotowych znaczników jak w HTML.

Jest często używany w konfiguracjach i wymianie danych.

Pliki XML są tekstowe.

Można je otworzyć w każdym edytorze.

Najczęściej zapisuje się je z rozszerzeniem .xml.

Budowa dokumentu XML

Dokument XML ma strukturę drzewiastą. Na samej górze znajduje się element główny.

Wszystkie inne elementy muszą być w nim zagnieżdżone.

Przykład:

<root>
  <user>
    <name>Jan</name>
    <age>17</age>
  </user>
</root>

Każdy element musi być poprawnie zamknięty.

Niedomknięty tag powoduje błąd.

W XML liczy się wielkość liter.

<User> i <user> to dwa różne elementy.

Struktura musi być spójna.

Nie można mieszać źle zagnieżdżonych tagów.

To odróżnia XML od HTML, który jest bardziej tolerancyjny.

Składnia XML

XML ma bardzo prostą składnię, ale jest rygorystyczna.

Każdy element wygląda jak znacznik HTML, ale jest definiowany przez użytkownika.

Przykład:

<book>
  <title>HTML dla początkujących</title>
  <author>Kowalski</author>
</book>

Elementy mogą mieć atrybuty.

Przykład atrybutu:

<book id="1" lang="pl">
  <title>XML podstawy</title>
</book>

Atrybuty są w cudzysłowie.

Można używać pojedynczych lub podwójnych.

Najczęściej używa się podwójnych.

XML nie pozwala na błędy składni.

Każdy błąd zatrzymuje odczyt pliku.

Prolog XML

Na początku pliku XML często znajduje się deklaracja XML.

Wygląda tak:

<?xml version="1.0" encoding="UTF-8"?>

Określa wersję i kodowanie znaków.

Dzięki temu system wie jak czytać plik.

UTF-8 jest najczęściej używane.

Obsługuje polskie znaki.

Prolog nie jest obowiązkowy, ale zalecany.

Pomaga uniknąć błędów kodowania.

Elementy i atrybuty

Elementy XML to podstawowe bloki danych.

Atrybuty dodają dodatkowe informacje.

Przykład:

<user id="10" role="admin">
  <name>Anna</name>
</user>

Elementy mogą być zagnieżdżone.

Atrybuty nie mogą zawierać struktury.

Dlatego dane lepiej trzymać w elementach.

Atrybuty są tylko dodatkiem.

XML nie narzuca ich znaczenia.

Przestrzenie nazw XML

Namespace w XML służy do unikania konfliktów nazw.

Można mieć dwa różne znaczenia tego samego tagu.

Przykład:

<h:table xmlns:h="http://example.com/html">
<f:table xmlns:f="http://example.com/furniture">

Każda przestrzeń ma swój prefix.

Pomaga to w dużych dokumentach.

Bez namespace mogłyby powstać konflikty.

Używa się ich w XML bardziej zaawansowanym.

Poprawność XML

XML musi być well-formed, czyli poprawnie zbudowany.

Każdy tag musi być zamknięty.

Nie można mieć błędów w strukturze.

Przykład błędu:

<user>
  <name>Jan
</user>

Brakuje zamknięcia </name>.

Taki plik nie zadziała.

Parser XML go odrzuci.

To bardzo ważna zasada.

DTD i XML Schema

DTD i XML Schema służą do definiowania struktury XML.

DTD jest starszy i prostszy.

XML Schema jest bardziej rozbudowany.

Pozwala określić typy danych.

Przykład DTD:

<!ELEMENT user (name, age)>

Schema XML jest bardziej nowoczesna.

Używa się jej w większych systemach.

Zastosowanie XML

XML używa się do wymiany danych między systemami.

Jest często w konfiguracjach aplikacji.

Stosowany w Androidzie i starszych API.

Przykłady:

  • pliki konfiguracyjne
  • wymiana danych między serwerami
  • formaty dokumentów

Obecnie często zastępowany przez JSON, ale nadal ważny.

Podsumowanie

XML to język do opisu danych, a nie wyglądu.

Jest bardzo rygorystyczny i wymaga poprawnej składni.

Ma zastosowanie w wielu systemach informatycznych.

Choć mniej popularny niż JSON, nadal jest używany.

Warto znać jego podstawy.
